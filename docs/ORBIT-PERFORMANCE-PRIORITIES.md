# Orbit AI and application performance priorities

The screenshot's credit/rate wrapping was a header layout issue. The header now aligns identity and controls on one row when space allows, and adapts to the conversation pane's actual width on smaller screens. A compact Usage button combines a credit ring with an accessible balance popover. The arc shrinks as shared organization credits are consumed and grows when the balance renews; it is not a provider-capacity or personal request meter. Numeric per-minute/hour/day caps are absent from the AI header and its popover; backend safeguards still apply. Agent Tracker uses a workflow icon; Activity keeps its activity trace. The AI display identity is Orbit AI; it does not rename the underlying Gemini provider or model.

Changes made here: header blur removed; animated blurred logo layers replaced with transform-only SVG motion; historical message marks stay static; idle animation is limited to the header/empty-state hero; reduced-motion preferences stop mark animation including the busy state. No animation library, raster asset, extra inference service or runtime dependency was added. Conversation pages no longer fetch the portfolio insights and starters used only on the empty chat page. Existing caching and requestAnimationFrame stream batching remain in use. These are code changes, not an end-to-end speed benchmark.

The credit arc and balance bar animate between server-reported values, with a low-balance color below 15%. The popover opens by keyboard or touch, closes with Escape or an outside click, and honors reduced-motion preferences. Local component previews at 1,100, 420 and 320 pixels verified that controls fit without horizontal overflow, including dark mode; simulated balance changes verified decreasing and increasing arcs. These previews used synthetic credits and made no AI calls.

## Next improvements, ordered by value

1. Record real time-to-first-token, answer completion, tool/query duration, queue wait, provider 429s and error rates by feature/tier. Report p50/p95 with request counts and context size. Use ordinary production telemetry and consented small examples, respecting the instruction against bulk AI tests.
2. Fix slow database queries before buying larger Railway machines: inspect PostgreSQL plans for authorized portfolio/workload/search routes, use composite tenant/project/status/due-date indexes where plans justify them, bound pagination and avoid fetching full document bodies for list views. Do not introduce guessed indexes or disable permission checks.
3. Reuse deterministic reads for exact counts, deadlines, assignments and finance; reserve Gemini for interpretation and explanation. Cache only with tenant, user/project/team scope, query and source-version/invalidation keys. Never share authorized results through a global semantic cache.
4. Keep route splitting already present in App.tsx. Further split heavy Settings/People sections and load document editing/chart code only on the screen that uses it. The current build puts roughly 208 kB in People, 144 kB in Settings, 462 kB in the editor and 328 kB in chart code before gzip; these are bundle sizes, not proven startup costs. Profile route load and interaction before moving code. Virtualize long lists where real rendering traces show a benefit.
5. Route cheap questions through Gemini Flash-Lite; escalate a tested subset to a more capable model only after accuracy and cost evaluations justify it. Keep tightly bounded output, evidence and tool rounds. In-flight request deduplication must be identity/tenant scoped. Stop abandoned model calls promptly and keep business confirmations durable.
6. Use bounded persistent workers for slow document/review/delivery work. For Slack, separate incoming admission, permission-aware execution and outgoing delivery so retries cannot rerun a paid answer. Add quiet hours and per-workspace fair dispatch before enabling notification workflows.
7. Before adding API replicas, implement shared local-fallback leases. The current one-slot Ollama backup cannot support a fleet of replicas with independent admission. Redis cloud admission does not protect local inference automatically. Add replicas only after measuring application/database/provider bottlenecks; CPU/RAM alone do not increase Gemini quota.
8. Add structured operational alerts for provider budget, failed ledger reconciliation, stuck jobs, slow queries, worker lag and Slack delivery failures. Budget notifications should precede service pauses. Keep unused integrations off and avoid duplicate UI polling or full-page reloads after every realtime event.

The platform's next quality milestone should be reliable, sourced, permission-correct answers and recoverable actions with measured latency. No release can honestly guarantee unlimited concurrency, perfect predictions or world-leading performance without workload evidence.

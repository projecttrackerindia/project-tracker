# AI credit accounting

Customer credits are plan units, not rupees or provider tokens. Existing plan grants and Quick/Standard/Deep prices remain authoritative. Conversations reserve their chosen tier price; one-shot summaries, risk reviews, search, triage and meeting-note extraction use the existing Quick price. Built-in greetings, confirmations and deterministic proactive reviews cost zero.

Each workspace/month has an account. The first reservation imports already recorded assistant credits as an opening movement. A short database transaction locks the tenant audit chain before the tenant row, checks spent plus outstanding reservations against the current entitlement, reserves the price and appends a ledger movement. PostgreSQL coordinates this across replicas; SQLite uses the same transaction boundary. The model runs after the transaction commits.

Settlement saves the assistant answer, audit and ledger charge together. Failed requests release the hold; stopped conversations retain the existing tier charge policy. Malformed one-shot JSON is not charged. Reservations expire after twenty minutes, longer than the maximum fifteen-minute agent deadline. The operations worker reconciles abandoned holds after a restart. Admission operation IDs are unique and cannot dispatch a model twice. Ledger entries are append-only in the persistence API.

AI inference rejects the HTTP `Idempotency-Key` middleware because its request-wide transaction would hold tenant locks while awaiting a provider. Confirmed business actions retain their execution bindings and idempotency support. Durable reviews accept stable request keys. A future background inference API should return a durable job receipt rather than replaying an SSE stream.

Owners and admins may enable user and team caps in Settings → AI usage. Caps limit new work after configuration; they do not mint credits or retroactively attribute older usage. They reset their counters in each UTC monthly account. A member's admitted work counts against their enabled user cap and each enabled team cap for their current memberships, plus an explicit team lens if provided. Organization credits are charged once. Budget holds retain attribution and policy version when membership or caps change before settlement. Zero is a valid blocking cap; disabling a cap stops new holds but preserves reconciliation of earlier ones.

New chat answers retain their provider price snapshot and completed-turn usage. Gemini 3.5 Flash-Lite uses the standard published token rates verified on October 10, 2026: USD 0.30 per million uncached input, USD 2.50 per million output including thinking, and USD 0.03 per million cached input. Source: [Google's Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing). Claude uses configured tier rates. Unknown models, interrupted turns and one-shot responses without token metadata are marked incomplete, not free. Estimates exclude taxes, grounding, cache storage, classifiers and local hosting. They are separate from the customer ledger and require reconciliation with provider invoices. Historical answers use current rates because they have no execution-time price snapshot.

No top-up credits are minted by a browser callback or manually supplied payment reference. Paid top-up packs require explicit server pricing, verified provider order/payment reconciliation and idempotent purchase receipts before activation. Slack and WhatsApp remain disabled until approved accounts are configured.

Gemini's shared pilot admission still reserves a pessimistic input estimate and maximum output before dispatch. Completed turns with explicit usage reconcile those reservations atomically to actual input (including cached input) and output (including thinking). Receipts expire after a day and settle at most once across replicas. Late completion cannot refund the next minute's token counter. Request/day counters are never refunded. Missing metadata, interrupted requests and failed Redis reconciliation retain conservative holds. Previous pilot usage is not reset or retroactively refunded. These provider ceilings remain separate from plan credits and actual prepaid account balance.

The scripted 100-user capacity benchmark is now opt-in through `PM_TEST_AI_BURSTS=true` or the manual CI input. Normal CI uses focused agent/credit regression tests and does not run that burst. Redis counter tests call no AI provider.
